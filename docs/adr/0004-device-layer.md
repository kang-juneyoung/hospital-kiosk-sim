# 0004. 장비 통신은 프레임 파서 + 드라이버 + 시뮬레이터로 나눈다

- 상태: 채택
- 날짜: 2026-10-01

## 배경
지폐 인식기·영수증 프린터 같은 장비는 RS-232C로 붙는다. 시리얼 포트는 한 번 읽을 때 프레임이 통째로 온다는
보장이 없고(조각나서 옴), 잡음 바이트나 체크섬이 깨진 프레임도 들어온다.
또 장비가 없는 개발 PC에서도 화면과 업무 흐름을 개발·테스트할 수 있어야 한다.

## 결정
- `SerialFrameParser`: 바이트를 쌓아 두고 STX~ETX+BCC 프레임을 복원한다. 잡음은 버리고, 체크섬이 틀리면 버린다.
- `BillAcceptorDriver`: 프레임을 "지폐 들어옴(금액)" 같은 이벤트로 바꾸고, 보관(S)·반환(R) 명령 프레임을 만든다.
  실제 장비에서는 `SerialPort.DataReceived`에서 `Feed`만 호출하면 된다.
- 카드 단말기·프린터·거스름돈 방출기는 인터페이스로 두고, 시뮬레이터로 승인·거절·응답 없음·용지 없음·방출 실패를 재현한다.
- BCC 범위(STX 포함 여부 등)는 장비마다 다르므로 사양서로 확인할 것을 코드 주석에 남긴다.

## 결과
- 테스트: 조각난 바이트 복원, 잡음·체크섬 오류 처리, 권종 거부, 거스름돈 부족 시 반환, 환불 실패 시 직원 호출.
- 실제 `System.IO.Ports` 연결 코드는 넣지 않았다(장비 사양이 없으므로). 드라이버의 `Feed`/`write` 경계까지만 구현.
