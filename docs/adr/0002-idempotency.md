# 0002. 이중 결제는 거래 키(멱등 키)와 DB UNIQUE 제약으로 막는다

- 상태: 채택
- 날짜: 2026-10-01

## 배경
터치 화면에서는 버튼이 두 번 눌리거나, 응답이 늦어 같은 요청이 다시 보내지는 일이 생긴다.
같은 수납 건을 동시에 창구에서 처리하는 경우도 있다.

## 결정
- 화면은 결제 시도마다 새 거래 키(GUID)를 만들고, 같은 시도의 재전송은 같은 키를 쓴다(`KioskSession.BeginPayment`).
- 서비스는 같은 키의 결제가 있으면 새로 승인하지 않고 기존 결과를 돌려준다.
- DB는 `payment.idempotency_key`에 UNIQUE 제약을 둔다. 서비스 검사를 동시에 통과해도 두 번째 INSERT가 실패한다.
- 수납 완료는 한 트랜잭션에서 대상 수납 건을 `FOR UPDATE`로 잠그고, 전부 `Unpaid`일 때만 바꾼다. 하나라도 이미 수납됐으면 아무것도 바꾸지 않는다.

## 결과
- 테스트: `같은_키로_두번_요청해도_승인은_한번만_일어난다`, `저장_직전에_다른곳에서_수납되면_트랜잭션이_전부_거부한다`
- MySQL 8.0에서 UNIQUE 위반(ERROR 1062)과 트랜잭션 SQL을 직접 실행해 확인했다.
